# AI 向け指示の改訂

改訂の前に `System/規則台帳.md` と `System/失敗記録.md` を読む。指示の変更は事前承認の対象なので、変更案を差分で示してから書く。

## 指示の置き場

- ハーネス固有の権限とフックは各設定に置き、共有の規則本文を複製しない。
- `AGENTS.md`: 常時読まれる指示の正本。Codex は直接、Claude Code は `CLAUDE.md` の `@AGENTS.md` から読む。全作業に関係し、スキルが呼ばれなくても守るべきものだけを置く。3,000字以内。
- `.agents/skills/<名前>/SKILL.md`: 作業ごとの手順と判断基準の正本。`.claude/skills` は同じディレクトリへのリンクで、Claude Code はそこから読む。説明文は「何をするか。いつ使うか」を120字以内で書く。
- `.agents/skills/<名前>/references/`: 判定の例や長い型。SKILL.md から一段で指す。
- `System/参照/`: 複数のスキルが共有する参照資料（Typst の記法表、学習支援の共通規則）。
- ディレクトリごとの `AGENTS.md` と、Claude Code の `paths` つきのルールは使わない。Codex は起動したディレクトリまでしか `AGENTS.md` を探さず、両ハーネスで振る舞いがずれるため。
- 規則の本文は一か所にだけ書き、ほかからはファイルと見出しで指す。

## 規則を足す前の確認

1. 起きた事象を失敗記録に書き、原因と守る目的を言えるか。言えなければ規則を作らない。
2. 権限、サンドボックス、フック、プラグインの設定で防げるか。防げるなら設定にし、文は書かない。
3. 既存の規則の目的に含まれるか。含まれるなら、その規則の文を直す。
4. 指示なしで代表的な作業をやり直して、問題が起きるか。起きなければ書かない。
5. 全作業で必要か（`AGENTS.md`）、特定の作業か（スキル）、まれに参照するか（参照ファイル）を決める。
6. 規則台帳に ID、目的、適用範囲、対象外、正本の場所、関連する失敗を書く。
7. 関係する代表的な作業をやり直して確かめる。

## 既存の指示の振り分け

一つの規則ごとに、上から順に問う。

| 問い | はい | いいえ |
| --- | --- | --- |
| Q1 守る目的を一文で言えるか | Q2へ | 削除の候補（利用者に確かめる） |
| Q2 道具や設定で担保できるか | 設定へ移して削除 | Q3へ |
| Q3 指示なしでも代表的な作業で守られるか（やってみて確かめる） | 削除 | Q4へ |
| Q4 同じ目的の規則がすでにあるか | 統合 | Q5へ |
| Q5 全作業で、スキルが呼ばれなくても守る必要があるか | `AGENTS.md` に残す | Q6へ |
| Q6 特定の作業でだけ必要か | 該当するスキルへ移す | 参照ファイルへ移す |

特定のノートへの個別の対処は、Q1 で目的に一般化してから判定する。一般化できないものは失敗記録にだけ残す。

## 書き方

規則ごとに短い理由を一度だけ添え、長い経緯は失敗記録に置く。行動は「何をするか」で書き、否定形は越えてはならない線（先回り、原本の変更、Vault 外への書き込みなど）に使って、守る目的を添える。太字や強い命令語による強調は使わない。例は判断の境目が微妙なものだけを参照ファイルに置く。用語は `AGENTS.md` の置き場と各スキルの正本に揃える。

## 失敗の記録

- 実際に起きた失敗だけを `System/失敗記録.md` に書く。事象、原因（判断の誤りとして）、守る目的、対応する規則の ID、状態（対応済み、観察中）を書く。
- 失敗を直すときは、その失敗が破った原則の正本を直す。「X をしない」という個別の禁止を足さない。
- 原因と守る目的を説明できるなら、似た失敗を一件にまとめてよい。
- 失敗記録は AI に常時読ませない。

## 見直す時機

新しい失敗を記録したとき、月次の振り返り、使うモデルやハーネスの版が変わったとき、`AGENTS.md` が3,000字を超えたとき。モデルやハーネスが変わったら代表的な作業をやり直し、不要になった規則を Q3 で削る。Claude Code では `/doctor prompt-audit` で矛盾と参照切れを確かめる。
