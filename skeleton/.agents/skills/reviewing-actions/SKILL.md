# タスクと振り返り

## 目印

| 記号 | 状態 | Tasksの状態型 |
| --- | --- | --- |
| `[ ]` | やる | TODO |
| `[/]` | やっている | IN_PROGRESS |
| `[w]` | 待ち | ON_HOLD |
| `[s]` | いつか | ON_HOLD |
| `[x]` | 済み | DONE |
| `[-]` | やめた | CANCELLED |

「待ち」には待つ理由を一言添え、「いつか」には日付を付けない。`📅` は明示された締切、`⏳` は実行予定日、`🛫` は着手可能になる最早日を表す。日次のファイル名から日付を推定しない。繰り返しは日付を基準にした定期作業に使える。毎月の固定日は、`when done` ではなく元の日付を基準にする。

## 置き場

行動のタスクは `LifeState/Action/`、`LifeState/Admin/`、`LifeLogs/Dailies/`、`LifeLogs/Reviews/` に配置する。一つの用事は一か所にのみ記述する。完了状態が食い違わないようにする。

`LifeState/` の置き場は、今の注意の向け方に応じて選択する。

| 置き場 | 配置するもの |
| --- | --- |
| `LifeState/Action/<名前>.md` | 今、能動的に注意を向けている取り組み。ゴールとプロジェクトで型を分けず、見渡して時間・労力の配分を決める |
| `LifeState/Admin/` | 今は忘れていたいが、忘れては困る対象。用事の書き方は `updating-records` に従う。 |
| `LifeState/Someday/<名前>.md` | 実施を約束していないが、選択肢として残したい取り組み。 |
| `LifeLogs/Archive/<名前>.md` | 今後の対応がなく、経緯や結果を参照するために残す取り組み。 |

注意の向け方が変わったら、ノートを移動する。能動的に注意を向ける時期でなくなった取り組みは、保存目的に応じて移動先を選択する。再開時期を忘れては困る場合や運用・管理が続くなら Admin、再開するかどうかが自由なら Someday、経緯を参照するためだけなら Archive に配置する。一時的に手を止めていても検討を続けている場合は Action に残す。移動させる際は `restructuring-vault` に従う。ノートを移動してもタスクの状態は変更しない。Someday や Archive へ移動する前に、まだ実行すべき用事が残っていないかを利用者に確認する。

生活の用事にはタスク行に `#生活` を付ける。期限全体の一覧にも生活分の一覧にも同じタスクが出る。

## チェックボックス

行動の抽出対象は、4つの行動パス（Action、Admin、Dailies、Reviews）のみに限定する。読書の演習や証明課題は専用の行動状態を作らず一覧の対象外にする。再検討や振り返りの状態はプロパティで表し、取り組みの状態は置き場で表現する。知識ノートの再調査は `AGENTS.md#常に守ること` を参照する。

習慣を新たに集計する必要が出たときは、記録する種類と単位を利用者に確かめる。未使用の習慣項目は日次テンプレートに並べない。

## Homeの一覧

| 一覧 | 掲載条件・見直す時機 |
| --- | --- |
| 今日・直近の期限 | 開始日が未設定か今日以前のTODO/IN_PROGRESSのうち、進行中か実行予定日・期限が今日以前のものと、済み・やめた以外で期限が14日後以前のもの（超過分も含む）。後者は待ち・いつかや開始日が未来のものも含む |
| 生活の用事／対応・日程確認 | `#生活` のTODO/IN_PROGRESSで、開始日・実行予定日が未設定か今日以前。日付なしも含む |
| 生活の用事／この先 | `#生活` のTODO/IN_PROGRESSで、開始日か実行予定日が未来。先の日付にも上限を設けない |
| 生活の用事内の待ち・いつか（折りたたみ） | `#生活` で状態記号が `w`・`s` のもの。待ちは週次、いつかは月次で見る |
| 全体を見直す（折りたたみ）／未完了 | TODO/IN_PROGRESSすべて。未来・日付なしも含め、ノートごとに分ける |
| 全体を見直す（折りたたみ）／待ち・いつか | 状態記号が `w`・`s` のものをノートごとに分ける。待ちは週次、いつかは月次で見る |
| 振り返り漏れ | 今週・今月のノートがないか、`completed` がtrueでない |
| 取り組み | `LifeState/Action/` 内のノートを見渡し、時間や労力の配分を決定する。 |
| あとで見返す（折りたたみ） | `review: true` のノート。時間のあるときに開く。印の扱いは `System/参照/プロパティ.md#再検討` に従う |

`not done` はON_HOLDも含むので、日常の一覧はTODO/IN_PROGRESSを明示する。待ち・いつかは状態記号 `w`・`s` で区別する。表示名の変更で一覧が変わらないようにするため。ノートの一覧と習慣の集計はBases、タスクはTasks、振り返りノートの不在だけはHomeのdataviewjsで判定する。

## 設定

TasksのGlobal Queryの正本は `.obsidian/plugins/obsidian-tasks-plugin/data.json`。一覧に出ないときは、行動パスと状態の条件を確認する。設定の変更の確認区分は `AGENTS.md#確認の境界` に従い、変更後はObsidianを再起動して表示を確かめる。

テンプレートに書いたクエリの中身は生成したノートにコピーされ、後から直せないため、日次にはクエリの中身を書かない。日次のテンプレートに置くのは、習慣プロパティ、固定のリンク、中身が別のファイルか設定にあるもの（`journal-nav`、`System/Bases/` の Base の埋め込み、`System/Views/` の処理を呼ぶ `dv.view`）に限る。タスクの一覧はHomeで保守する。

## 振り返り

週次 `LifeLogs/Reviews/YYYY-Www` はその週の月曜、月次 `LifeLogs/Reviews/YYYY-MM` は月初に利用者がJournalsで作る。自動生成や繰り返しタスクにはしない。存在だけで完了とみなさず、実施済みの付け方は `System/参照/プロパティ.md#振り返り` に従う。

週次では前週の完了・中止、習慣の実施日数と合計、取り組みごとの予定と実際の行動量、待ちを振り返り、Inbox処理で [[System/Bases/未処理.base#知識候補]] から知識候補を判断し、今週の配分を決める。細かいタスクは必要なら週次に自由に書く。

月次振り返りでは前月の成果目標と行動目安を見直し、いつかのタスクおよび `LifeState/Someday/` の取り組みを確認して、Action へ移動するものや次の配分を決定する。ジャズ練習の伴走は `jazz-mentor` を使う。

## 旧記法からの移行

新たに「いつか」にするタスクには予定日や期限を付けない。移行済みのタスクに既にある作成日・開始日などは、履歴として保持し、自動で消さない。旧習慣・学習チェックは元のチェック状態と本文・日付を見える履歴行として残し、習慣の種類・単位を推測でプロパティにしない。
