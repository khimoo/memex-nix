# タスクと振り返り

## 目印

| 記号 | 状態 | Tasksの状態型 |
| --- | --- | --- |
| `[ ]` | やる | TODO |
| `[/]` | やっている | IN_PROGRESS |
| `[w]` | 待ち | ON_HOLD |
| `[s]` | いつか | ON_HOLD |
| `[x]` | 済み | DONE |
| `[-]` | やめた | CANCELLED |

「待ち」には待つ理由を一言添え、「いつか」には日付を付けない。期限が明示されたときだけ `📅`、その日にやると決めたときだけ `⏳` を付ける。日次のファイル名から予定日を推定しない。繰り返しは期限のある定期作業に限る。自分で進める行動と保留を区別するため。

## 置き場

行動のタスクは `Action/`、`Dailies/`、`Reviews/` に置く。

プロジェクトは `Action/<名前>.md` に `kind: project` を付け、本文にタスク、`goal` に貢献するゴールへのリンクのリストを持つ。空なら独立した活動。`status` は `active`、`someday`、`done`、`dropped`。終了時は状態を変えて同じ場所に残す。

ゴールもActionに置き、`kind: goal`、`status` は `active`、`paused`、`done`、`dropped`、`idea`。成果目標と自分で調整できる行動の目安を分ける。`focus` は `注力`、`維持`、`休止`（空なら維持）。注力数の上限は設けず、配分は利用者が決める。`status` が空のノートは「状態未設定」で扱う。

## チェックボックス

行動の抽出は三つの行動パスに限る。読書の演習や証明課題は専用の行動状態を作らず一覧の対象外にする。ノートの状態はプロパティで表す。知識ノートの再調査は `AGENTS.md#常に守ること` を参照する。

習慣は日次プロパティに記録し、量はnumber、実施の有無はcheckbox型にする。名前は英小文字一語で習慣名を表し、未実施日は空欄。種類と単位は利用者が決める。タスクのチェックボックスにはしない。期限切れを積み上げないため。

## Homeの一覧

| 一覧 | 掲載条件・見直す時機 |
| --- | --- |
| 今日の行動 | TODO/IN_PROGRESSで、進行中か、予定日か期限が今日以前 |
| 期限 | 済み・やめた以外で期限が14日以内。期限のある待ちも含む |
| 未完了 | TODO/IN_PROGRESSすべて。日付なしも含め、プロジェクト・ノートごとに分ける |
| 待ち | 状態記号が `w`。週次で見直す |
| いつか | 状態記号が `s`。月次で見る |
| 振り返り漏れ | 今週・今月のノートがないか、`reviewed` がtrueでない |
| 未処理 | Inboxの件数と古い順の一覧への入口 |

`not done` はON_HOLDも含むので、日常の一覧はTODO/IN_PROGRESSを明示する。待ち・いつかは状態記号 `w`・`s` で区別する。表示名の変更で一覧が変わらないようにするため。ノートの一覧と習慣の集計はBases、タスクはTasks、振り返りノートの不在だけはHomeのdataviewjsで判定する。

## 設定

TasksのGlobal Queryの正本は `.obsidian/plugins/obsidian-tasks-plugin/data.json`。一覧に出ないときは、行動パスと状態の条件を確認する。設定の変更の確認区分は `AGENTS.md#確認の境界` に従い、変更後はObsidianを再起動して表示を確かめる。

テンプレートに書いたクエリの中身は生成したノートにコピーされ、後から直せないため、日次にはクエリの中身を書かない。日次のテンプレートに置くのは、習慣プロパティ、固定のリンク、中身が別のファイルか設定にあるもの（`journal-nav` と、`System/Bases/` の Base の埋め込み）に限る。タスクの一覧はHomeで保守する。

## 振り返り

週次 `Reviews/YYYY-Www` はその週の月曜、月次 `Reviews/YYYY-MM` は月初に利用者がJournalsで作る。自動生成や繰り返しタスクにはしない。存在だけで完了とみなさず、終えたら `reviewed: true` にする。

週次では前週の完了・中止、習慣の実施日数と合計、注力ゴールごとの予定と実際の行動量、待ち、Inboxの処理を振り返り、今週の配分を決める。細かいタスクは必要なら週次に自由に書く。

月次では前月の成果目標と行動の目安を見直し、いつかを眺め、次の配分を決める。ジャズ練習の伴走は `jazz-mentor` を使う。

## 旧記法からの移行

新たに「いつか」にするタスクには予定日や期限を付けない。移行済みのタスクに既にある作成日・開始日などは、履歴として保持し、自動で消さない。旧習慣・学習チェックは元のチェック状態と本文・日付を見える履歴行として残し、習慣の種類・単位を推測でプロパティにしない。
