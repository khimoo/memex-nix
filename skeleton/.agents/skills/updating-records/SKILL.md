# 実務資料の更新

`LifeState/Admin/` は、今は忘れていたいが、忘れては困る対象を保管する場所。必要なときに事実を正確に参照でき、注意を向けるべきタイミングを把握できるようにする。

## 規則

- Zettelkasten の方法論を適用しない。Zettel にせず、構造ノートにもつながない。
- 確認した値と未確認の値を分ける。あとで見返したいと選んだときの印は `System/参照/プロパティ.md#再検討` に従う。
- ノートにはタグを付けない（object tag も含め付与しない）。タスク行に付ける `#生活` は例外とする。
- 原本や事実をたどれるリンクを置く。
- 対象となる用事は、該当ノート内にタスクとして記載してよい。生活に関連する用事には `#生活` を付与する。一つの用事は一か所にのみ記載する（日次ノートなどに書いた内容と重複させない）。
- 完了済みのタスク行は作業完了の記録であり、解約日や開通日のような契約上の日付根拠としては扱わない。用事によって値が変更された場合は、以下の規則に従って現在値と履歴を更新する。
- 次に注意を向けるべき条件（更新日や維持条件など）が明確な対象は、その条件と根拠を本文に記述し、把握が必要な時期にタスクを配置する。条件が存在しない対象に対しては見直し日を設定しない。
- 能動的に注意を向ける時期を迎えた対象は、利用者に確認したうえで `LifeState/Action/` へ移動する（`reviewing-actions` の「置き場」を参照）。
- 値と日付（残りの単位数、契約の更新日、型番など）は、対象との対応が分かるよう本文に書く。必要なときに原本や現物を確かめ、確認した日と根拠をその値に添える。
- 原本の保護は `AGENTS.md#常に守ること` に従い、リンクで開くか、本文で表示する必要があれば `![[...]]` で埋め込む。PDF などの実体を Git で管理するかは `restructuring-vault` の「資料の保存」による。
- 検索から隠さない。素早く引くのが目的なので、Obsidian の除外設定に入れない。
- 値を変えたら、本文の現在値と根拠を更新し、「履歴」の節に「日付、旧値から新値、根拠」を書き足す。

一つの対象を1ノートにし、現在値と過去の変更を区別する。昔の請求日から現在の用事や繰り返しを推測して作らない。

本文の構造の目安は `references/構造.md` にある。
