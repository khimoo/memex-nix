# 実務資料の更新

`LifeState/Admin/` は、考えではなく、必要なときに正確に引く事実を置く棚。

## 規則

- Zettelkasten の方法論を適用しない。Zettel にせず、構造ノートにもつながない。
- 出自と再調査の適用範囲は `AGENTS.md#常に守ること` に従う。
- タグを付けない（object tag も付けない）。
- 思考のノートへ wikilink でつながない。Admin の中でのリンクはよい。
- チェックボックス `- [ ]` を使わない。実務の状態は値とプロパティで表すため。
- 値と日付（残りの単位数、契約の更新日、型番など）は、本文に散らさず frontmatter に書く。
- 原本は `Assets/Originals/` を読むだけとし、リンクで開くか、本文で表示する必要があれば `![[...]]` で埋め込む。PDF などの実体を Git で管理するかは `restructuring-vault` の「資料の保存」による。
- 検索から隠さない。素早く引くのが目的なので、Obsidian の除外設定に入れない。
- 値を変えたら、確認日 `confirmed` と根拠のリスト `evidence` を更新し、本文の「履歴」の節に「日付、旧値から新値、根拠」を書き足す。

契約の更新日は `renew`、期限は `due` に書く。一つの対象を1ノートにし、現在値と過去の変更を区別するため。

構造と frontmatter の目安は `references/構造.md` にある。
