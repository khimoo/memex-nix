# Vault運用ガイド

このVaultでは、再確認したい知識、汎用的に活用できる思考、読書ノートや作業記録、日々のタスクや実務を一元的に管理する。全体の入り口は [[Home]] である。各ルールの目的と正本は [[System/規則台帳]] を参照すること。

## 置き場

| 場所                           | 置くもの                                                      |
| ---------------------------- | --------------------------------------------------------- |
| `Knowledge/Wiki/`                      | 学問・技術・歴史などの体系に組み込まれている知識（定義・仕様・定理など）。抽象度の階層で置き |
| `Knowledge/Zettel/`                    | 自分の経験と思考から生まれた知識（考察、手順や操作の覚え書き、判断の記録、出会った人物や作品）。構造ノートは関係の説明とリンクを持つ |
| `Knowledge/Reading/<資料が分かる名前>/`         | 資料ごとの章別メモ、行間の考察、演習、予想、実測値やログ。既存フォルダ名は保つ  |
| `Inbox/`                     | 知識候補と、保存して参照するWebクリップを分けて置く。            |
| `Knowledge/Writing/`                   | 結論が出るかもしれない持論と、その材料・構成を置く                              |
| `LifeState/Action/`                    | 今、能動的に注意を向けている取り組みと、そのタスクを置く               |
| `LifeState/Someday/`                   | 実施を約束していないが、選択肢として残したい取り組みを配置する。             |
| `LifeLogs/Dailies/`・`LifeLogs/Reviews/`        | 日々の記録やログ、週次・月次の振り返りを行う                                    |
| `LifeLogs/Archive/`                    | 今後の対応がなく、経緯や結果を参照するために残す取り組みを配置する。                      |
| `LifeState/Admin/`                 | 今は忘れていたいが、忘れては困る対象（契約・機器・住まいなど）。事実や根拠・原本へのリンク、変更履歴と、その対象の用事を本文に記述する。 |
| `Assets/attachments/` | Obsidianで貼り付けた画像などの添付。その他の資料は用途に合わせて配置する |
| `System/`                    | システム設計、計画、規則台帳、失敗記録、Bases、共有参照などを管理する                     |
| `.scratch/`                  | AIの作業出力、中間成果物、退避ファイル、検証ログなどを一時保管する。Git管理外                 |

過去の記録の `_scratch/` は `.scratch/` に読み替えてください。


## 知識と読書

ノートの配置先は、その知識がどこで組み立てられたかで判断する。学問や技術や歴史のように外の体系に組み込まれている知識は Wiki、自分の経験と思考から生まれた知識は Zettel、生活の管理は Admin に置く。ファイル名やタグ、書籍の章立てなどを判断基準にしない。詳しい判断基準については `.agents/skills/editing-knowledge/SKILL.md` を参照すること。

精読・予想・演習のプロセスでは、人間が思考すべき領域をAIが先回りして埋めてはならない。また、既存の文章や証明は、明示的な依頼がない限り勝手に改作しないこと。AIが記述した知識の扱い、再検討の印、根拠の提示方法については、[AGENTS.md](AGENTS.md) の「常に守ること」に従う。数式にはTypst記法を用い、記法の対応表は [[System/参照/Typst記法]]を参照すること。

## 行動と振り返り

タスクは `LifeState/Action/`、`LifeState/Admin/`、`LifeLogs/Dailies/`、`LifeLogs/Reviews/` 内のチェックボックスから抽出する。ステータスは、`[ ]`（未着手・やる）、`[/]`（進行中・やっている）、`[w]` 待ち、`[s]`（いつかやる）、`[x]`（完了・済み）、`[-]`（中止・やめた）で表す。「待ち」にする場合は理由を明記すること。なお、日次ノートのファイル名から予定日を自動推定することはせず、期日のない未完了タスクも [[Home]] に表示する。

期日を設定した場合は `📅`、その日に実行すると決めた場合は `⏳` を付与する。新しく追加した「いつかやる」タスクには、予定日や期日を設定しない。既存タスクの作成日や開始日などのメタデータはそのまま維持する。

習慣の集計が必要になったときは、種類と単位を利用者が決めてから記録方法を選ぶ。雛形には未使用の項目を並べない。

取り組みの状態は置き場で表し、注意の向け方が変わったらノートを移動する（[[System/参照/プロパティ#取り組み]]）。振り返りの実施済みは [[System/参照/プロパティ#人が扱う項目]] に従う。Home では Action の取り組み全体を見渡し、月次で Someday を見直す。週次・月次は利用者が Journals から作り、実施したらチェックする。催促するのは今週・今月だけ。

あとで見返したいノートは [[System/参照/プロパティ#再検討]] の印を付ける。通常の新規作成では YAML 設定は不要。

行動は [[Home]] で確認し、知識候補は週次振り返りのInbox処理で [[System/Bases/未処理.base#知識候補]] から判断する。事実や参照資料は `LifeState/Admin/` から探し、以前の一覧や配置はGitの履歴で確認する。なお、Tasksプラグインの設定を変更した際は、プラグインの再読み込みが必要となる。

## 保存とAI指示

資料の配置、Git管理、同期、本文での表示は別々に判断する。クリップボードから貼った画像とドラッグ＆ドロップの添付は、Obsidian標準の保存先 `Assets/attachments/` を使う。その他の資料は使う文脈に合わせて置き場所を決める。原本の保護と出典の示し方は [AGENTS.md](AGENTS.md#常に守ること)、保存の判断は `.agents/skills/restructuring-vault/SKILL.md#資料の保存` に従う。

ノート本文はGitで同期する。資料のGit管理対象は `.gitignore` で指定する。Drive同期の対象は `.drive-sync-filter` で明示する。新規Vaultでは対象を指定するまで同期しない。設定と手動初期化の手順は [memex-nix README](https://github.com/khimoo/memex-nix#readme) を参照する。退避データは、利用者が保持期限を決めるまで削除しない。

全環境共通のAI向け指示は [AGENTS.md](AGENTS.md) に記載する。Claude Codeは [CLAUDE.md](CLAUDE.md) 経由で `@AGENTS.md` を読み込み、Codexは直接参照する。各スキルは `.agents/skills/` に配置し、`.claude/skills` から同じ実体を参照する。実行環境ごとの制約は `.claude/` や `.codex/` で管理する。Gitのコミットおよびリモートへのpushはユーザー自身が行う。

## Feature / 今後検討したいこと

過去資料の検索、出典付きノート、参考文献出力などが実際に必要になったとき、AIがその必要を捉えて仕組みを再検討する。
