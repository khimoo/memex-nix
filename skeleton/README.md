# Vault運用ガイド

このVaultでは、再確認したい知識、汎用的に活用できる思考、読書ノートや作業記録、日々のタスクや実務を一元的に管理する。全体の入り口は [[Home]] である。各ルールの目的と正本は [[System/規則台帳]] を参照すること。

## 置き場

| 場所                           | 開く目的                                                      |
| ---------------------------- | --------------------------------------------------------- |
| `Wiki/`                      | 対象の定義・仕様・手順・定理などを再確認する。各領域の入り口ノートは `kind: index` とする      |
| `Zettel/`                    | 1つの思考やアイデアを別の文脈へ展開・発展させる。構造ノートは `kind: structure` とする     |
| `Reading/<citekey>/`         | 文献ごとの章別メモ、行間の考察、演習、予想、実測値やログ。citekeyにはpapisに登録されたrefを用いる  |
| `Inbox/`                     | 未整理のアイデアやWebクリップを一時保管する。既存の素材は従来の階層構造を維持して収容する            |
| `Writing/`                   | 外部向けに発信する原稿と、その執筆に必要な素材を管理する                              |
| `Action/`                    | 目標（ゴール）、プロジェクト、テーマごとのタスク・行動リストを管理する                       |
| `Dailies/`・`Reviews/`        | 日々の記録やログ、週次・月次の振り返りを行う                                    |
| `Resources/`                 | 実務の値（未確認の値も含む）と、その確認日および根拠を記録する                           |
| `Originals/`                 | 再取得できない原本。AIは参照（読み取り）のみ行い、編集しない。元の同期コピーは当面の間保持する          |
| `attachments/`・`references/` | 添付ファイル、採用した生成物、papis管理の文献。現在はGit管理から除外し、Google Driveで同期する |
| `System/`                    | システム設計、計画、規則台帳、失敗記録、Bases、共有参照などを管理する                     |
| `_scratch/`                  | AIの作業出力、中間成果物、退避ファイル、検証ログなどを一時保管する。Git管理外                 |


## 知識と読書

ノートの配置先は、「何を調べ直すか」「どの思考を別の場面へ持ち出すか」という観点から判断する。分類はあくまで「ノートを開く目的」に基づいて行い、ファイル名やタグ、書籍の章立てなどを判断基準にしない。詳しい判断基準については `.agents/skills/editing-knowledge/SKILL.md` を参照すること。

精読・予想・演習のプロセスでは、人間が思考すべき領域をAIが先回りして埋めてはならない。また、既存の文章や証明は、明示的な依頼がない限り勝手に改作しないこと。AIが記述した知識の扱い、再調査の手順、根拠の提示方法については、[AGENTS.md](AGENTS.md) の「常に守ること」に従う。数式にはTypst記法を用い、記法の対応表は [[System/参照/Typst記法]]を参照すること。

## 行動と振り返り

タスクは `Action/`、`Dailies/`、`Reviews/` 内のチェックボックスから抽出する。ステータスは、`[ ]`（未着手・やる）、`[/]`（進行中・やっている）、`[w]` 待ち、`[s]`（いつかやる）、`[x]`（完了・済み）、`[-]`（中止・やめた）で表す。「待ち」にする場合は理由を明記すること。なお、日次ノートのファイル名から予定日を自動推定することはせず、期日のない未完了タスクも [[Home]] に表示する。

期日を設定した場合は `📅`、その日に実行すると決めた場合は `⏳` を付与する。新しく追加した「いつかやる」タスクには、予定日や期日を設定しない。また、旧環境から移行した既存タスクの作成日や開始日などのメタデータはそのまま維持する。

習慣の記録は、日次ノートの数値型やチェック型のプロパティで行う。記録する習慣の種類や単位は、運用の過程でユーザー自身が決定する。移行前のチェック記号・本文・日付は履歴行として残してあり、未実施の項目を通常のタスクの未完了として扱わないようにする。

ゴールのリソース配分は、プロパティで `focus: 注力/維持/休止`（未指定時は「維持」）と設定する。達成すべき「成果目標」と、自力でコントロールできる「行動の目安」は明確に区別する。「注力」に指定するゴール数に上限は設けない。週次や月次の振り返りノートはユーザーがJournalsから作成し、完了したら `reviewed: true` を設定する。Home上に、未作成と未完了の振り返りを一覧表示する。詳細な運用手順は `.agents/skills/reviewing-actions/SKILL.md` を参照すること。


## 保存とAI指示

資料の配置場所、Git管理の有無、同期方法、ノート本文での表示方法は、それぞれ個別に判断する。AIは原本（`Originals/`）に対して読み取りのみ行い、直接編集してはならない。ノート本文はGitを用いて同期する。一方、`Originals/` は各PC上に保持し、必要に応じてワークフローの原本同期を有効にする。ファイルが削除・上書きされた場合、同期処理によって同期対象外のディレクトリへ自動的に退避される。退避データの保持期限は未定であるため、既存の `attachments/` 側にあるコピーや今回退避されたデータは削除しないこと。文献はpapisで一元管理し、本文中では `[@citekey]` の形式で参照する。papisに未登録の資料に対して、推測でcitekeyを付与してはならない。

全環境共通のAI向け指示は [AGENTS.md](AGENTS.md) に記載されている。Claude Codeは [CLAUDE.md](CLAUDE.md) 経由で `@AGENTS.md` を読み込み、Codexは直接参照する。各スキルは `.agents/skills/` に1つだけ配置し、`.claude/skills` からは同じ実体を参照させる。実行環境（ハーネス）ごとの制約は `.claude/` や `.codex/` で管理する。原本ファイル、指示書、設定ファイルを通常のノートのように安易に編集対象としてはならない。Gitのコミットおよびリモートへのpushはユーザー自身が行う。
